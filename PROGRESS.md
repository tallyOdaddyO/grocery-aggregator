## Phase 2 — Database & Models ✅ COMPLETE

**9 tables:** `retailers`, `stores`, `products`, `product_variants`, `prices`,
`price_observations`, `product_matches`, `shopping_lists`, `shopping_list_items`.

**Dialect-aware JSON (per review feedback).**
`app/db/types.py` defines `JSONVariant = JSON().with_variant(JSONB, "postgresql")`.
Verified: PG DDL emits 4 `JSONB` columns, SQLite emits `JSON`. `jsonb_gin_index()`
declares GIN indexes with `.ddl_if(dialect="postgresql")` so
`ix_products_attributes_gin` and `ix_matches_signals_gin` exist on PostgreSQL for
containment queries and are skipped entirely on SQLite.

**`EnumString` TypeDecorator.** Columns declared `Mapped[SomeEnum]` were backed by
plain `String` and silently returned `str` after a DB round-trip, so `.value` raised
and identity checks were always False. `EnumString` stores the string value and
loads the enum member back, and rejects unknown values at INSERT rather than
persisting a status later code would have to guess at. Native PG `ENUM` was avoided
deliberately — adding a value would require a migration.

**Alembic.** `env.py` reads the URL from settings (not `alembic.ini`), enables
`render_as_batch` on SQLite (SQLite cannot `ALTER` most columns), and filters
PG-only indexes out of autogenerate so `alembic check` does not report phantom drift
on SQLite. The autogenerated migration needed two hand fixes: it emitted an
unimported `Text()` (a `NameError` on migrate), and it could not carry the `ddl_if`
gate, so GIN creation is re-gated in the migration via `_create_gin_index`.
Verified `upgrade head` → `downgrade base` → `upgrade head`, then `alembic check`
clean.

**Seed script** (`scripts/seed.py`), idempotent. All 8 retailers seeded as
`unavailable` with a written reason, because no connector exists yet — claiming
`active` would assert a capability we don't have. All 8 stores carry
`address_verified=False` and a **null address**: ZIP and city are the only location
facts asserted. Store numbers and street addresses are left blank rather than
invented, since a plausible fake address silently poisons every price attached to it.

**Tests: 27 passing** (`backend/tests/`) — dialect portability (JSONB vs JSON, GIN
present/absent), enum round-trip and rejection, provenance ranking completeness,
integer-cent exactness, unique `(variant, store)` price, FK enforcement under
`PRAGMA foreign_keys=ON`, append-only history surviving a price update, and seed
idempotency + no-fabrication assertions.
